# 설치와 연결

## Windows 앱

1. 검토한 설치 파일을 실행해 사용자별로 설치합니다. 현재 파일은 **미서명**입니다.
2. 처음 실행하면 빈 일정·보드·뉴스·결과함이 표시됩니다. 로컬 일정과 보드는 연결 없이 사용 가능합니다.
3. 기본 데이터는 Electron의 Windows 사용자 데이터 폴더 `%APPDATA%/orbit-desktop`에 저장됩니다. `ORBIT_DATA_DIR`를 지정한 경우 그 폴더가 기준입니다. `state.json`, 직전 `.backup`, DPAPI로 암호화한 `github.secret`/`alpha.secret`, `logs/`를 사용합니다. 설정에서 백업·복원·로컬 삭제를 제공합니다.
4. 설치 제거는 Windows 설치된 앱 또는 설치 폴더의 제거 프로그램을 이용합니다. 앱 제거는 사용자 데이터를 보존합니다. 완전 삭제 전에는 원격 예약을 중지하고 앱 설정의 로컬 초기화를 수행합니다. 원격 Issue/PR은 로컬 삭제로 제거되지 않습니다.
5. 0.1.4부터 앱 상단과 설정에서 새 버전 다운로드와 재시작·설치를 선택할 수 있습니다. 0.1.3 이하에서 처음 한 번은 updater가 포함된 새 설치 파일을 설치해야 합니다. 이후에는 별도로 설치 파일을 찾지 않아도 앱 내부에서 업데이트할 수 있습니다. 보관한 이전 설치 파일로 rollback할 수 있지만 미래 스키마는 이전 앱이 덮어쓰지 않습니다. 0.1.1은 외부 공급자를 위해 스키마2로 전환하고 이전 state.json을 state.json.v1.backup으로 한 번 보존합니다. 0.1.0으로 돌아가려면 앱 종료 후 스키마1 백업을 별도 폴더에 복사해 사용하고 새 스키마2 데이터를 보존하세요. 되돌린 백업 이후의 변경은 이전 앱에서 읽을 수 없습니다.

0.1.3은 정치 주제 저장을 위해 스키마3을 사용하며 스키마1/2를 자동 이전합니다. 이전 파일은 `state.json.v1.backup` 또는 `state.json.v2.backup`으로 보존합니다. 이전 앱으로 돌아갈 때는 해당 버전 백업을 별도 데이터 폴더에 복사하고 최신 데이터를 보존하세요. 로컬 초기화는 버전 백업도 삭제합니다.

## 앱 업데이트 배포와 확인

새 개발/CI 환경에서 npm이 의존성 설치 스크립트를 실행하지 않으면 npm ci 후 `node node_modules/electron/install.js`로 공식 Electron 실행 파일을 설치합니다. 검증/배포 workflow는 이 단계를 명시적으로 실행합니다. 타입 검사·번들 빌드만 통과하고 Electron binary가 없는 상태를 앱 실행 검증 성공으로 간주하지 않습니다.

- 배포 담당자는 package.json/lockfile 버전을 변경하고 검증 후 정확히 일치하는 v<version> 태그를 push합니다. release.yml은 Windows 검사·E2E·NSIS 생성·packaged 실행을 통과한 경우에만 공개 릴리스를 만듭니다. PR 생성 자체는 릴리스/설치 완료가 아닙니다.
- GitHub Releases에는 같은 빌드의 NSIS exe, exe.blockmap, latest.yml이 함께 있어야 합니다. 패키지 안 resources/app-update.yml은 DmzChile/Orbit에 고정됩니다. 앱의 GitHub 개인 토큰을 업데이트 피드에 전달하지 않습니다. 공개 업데이트 읽기는 별도 API 키가 필요 없습니다.
- electron-updater 6.8.11(MIT, electron-builder 26 호환)을 사용합니다. production 라이선스 고지는 빌드 시 재생성됩니다. 자동 다운로드·일반 종료 시 자동 설치·prerelease·downgrade·web installer는 비활성입니다. NSIS 다운로드의 SHA-512 검증과 공급자의 구성된 서명 검증을 끄지 않습니다. 현재 빌드는 미서명입니다.
- 자동 확인은 시작 후, 정상 응답 후 4시간, 실패 시 1/2/4/8/15분 backoff로 수행합니다. 절전 복귀와 인터넷 재연결도 같은 backoff를 적용합니다. 설정의 직접 확인은 즉시 재시도합니다. 다운로드 실패는 재시도 행동을 유지하며 자동으로 설치하지 않습니다.
- 설치 전 작성 중인 폼을 저장하고 재시작 확인을 누릅니다. 앱은 창 상태 저장·보류 중인 저장 완료·데이터 잠금 해제 후 NSIS를 실행합니다. 다운로드만 해 두고 앱을 닫으면 설치하지 않습니다. 사용자 데이터 삭제 옵션은 꺼져 있습니다.
- 검증: 두 버전의 실제 릴리스를 순서대로 배포하고 이전 버전에서 새 버전 감지→오프라인/재연결→다운로드→체크섬 검증→사용자 확인→업그레이드→일정·보드 유지→rollback을 확인합니다. 개발 실행에서는 updater가 비활성인 것이 정상입니다. mock/UI fixture 통과는 공개 릴리스 간 실제 업그레이드의 증거가 아닙니다.

## GitHub 연결

[GitHub의 fine-grained token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)을 만들고 **필요한 저장소만** 선택하세요.

| 권한 | 용도 |
|---|---|
| Metadata 읽기 | 계정·저장소 식별 |
| Contents 읽기 | 브랜치·기준 SHA |
| Issues 읽기/쓰기 | 요청·예약·영속 큐 댓글 |
| Actions 읽기 (선택) | GitHub Actions 산출물 다운로드 |
| Pull requests 읽기 | 활동과 결과 확인 |

토큰을 Orbit 설정에서 연결하고 앱에서 허용할 저장소를 체크하세요. 연결 해제는 로컬 암호문을 폐기합니다. 공급자 쪽 토큰 철회는 GitHub에서 별도로 수행합니다. 토큰 만료/권한 철회/읽기 전용/404/API 한도를 구별해 표시합니다.

GitHub에 전송한 요청·결과는 대상 저장소의 공개 범위를 따릅니다. 개인 요청을 공개 저장소에 게시하지 않으려면 비공개 테스트 저장소를 선택하세요.

## 외부 ChatGPT 예약 연결 (기본)

**GPT API 키 없이** 사용합니다. Orbit은 ChatGPT 예약을 직접 생성하지 않습니다. 사용자가 별도로 만든 ChatGPT 작업이 GitHub 요청을 읽고 결과를 게시합니다. [공식 예약 안내](https://learn.chatgpt.com/docs/automations)의 계정·작업 도구·실행 환경 조건을 직접 확인하세요.

1. GitHub를 연결하고 대상 저장소를 허용합니다. 요청과 첨부를 공유하는 데 동의한 뒤 **GitHub에 등록**합니다. GPT API key, 별도 AI secret, Orbit API workflow 설치가 필요하지 않습니다.
2. 요청 편집 화면의 **예약 프롬프트 복사**를 누릅니다. 실제 Issue 주소·최신 요청 확인·규칙 읽기·중복 방지·결과 형식이 포함됩니다.
3. GitHub 접근이 가능한 ChatGPT 작업에 붙여 넣고, ChatGPT에서 반복 시각/시간대·모델·도구 권한·실행 환경을 직접 설정합니다. Orbit의 예정 시각은 요청 정의이며 실제 ChatGPT 예약을 보장하는 상태가 아닙니다.
4. **지금 실행**은 같은 요청 Issue에 `orbit-queue:v1` 댓글을 전달합니다. 외부 작업이 확인해야 시작합니다. 전송 성공을 AI 완료나 ChatGPT 예약 생성으로 표시하지 않습니다.
5. 외부 작업은 `AGENTS.md`와 `docs/REQUIREMENTS.md`를 실제 checkout에서 읽고 최신 SHA·요청 사본·규칙 해시를 고정합니다. 작업 브랜치/검증/PR과 실제 산출물을 만든 뒤 동일 Issue에 `orbit-run:v1` JSON 댓글을 게시합니다. 상세 계약은 [외부 ChatGPT 계약](EXTERNAL_CHATGPT.md)을 참조하세요.
6. 결과 게시자는 Orbit에 연결한 GitHub 계정이 기본입니다. 다른 봇/계정을 쓰면 **설정 → 추가 결과 게시 계정**에 정확한 로그인 이름을 추가·저장합니다. 임의 작성자·다른 요청/저장소·실패한 검사로 성공한 레코드는 수용하지 않습니다.
7. 수동 1회 실행으로 실제 게시·결과 수신·산출물을 검증한 뒤 ChatGPT 예약을 활성화하세요. Orbit은 기본60초마다 인증된 결과를 조회하며 앱 재시작 시 누락 결과를 복구합니다.

예약 편집·일시정지·재개·삭제는 GitHub 정의를 수정/닫습니다. 외부 작업도 매번 최신 Issue의 enabled/consent/상태/종료 조건을 확인해야 합니다. 외부 ChatGPT 예약 자체를 중지하려면 ChatGPT에서도 중지합니다. 앱의 취소는 협력적 취소 댓글이며 외부 작업이 확인하기 전 즉시 종료를 보장하지 않습니다. 앱 종료 중 실행 가능 여부는 외부 작업의 환경에 달려 있습니다. 로컬 ChatGPT 프로젝트 작업은 PC 전원/앱 실행이 필요할 수 있습니다.

### 이전 OpenAI API worker (선택, 기본 비활성)

이전 `github-actions-openai` 요청을 보존하기 위해 코드가 남아 있습니다. 새 요청은 외부 ChatGPT로 저장하며 API worker가 처리하지 않습니다. 기존 API 요청을 외부 방식으로 전환하려면 편집→공유 동의→GitHub에 변경 반영 후 예약 프롬프트를 연결하세요.

API worker를 별도로 사용할 때만 `.github/workflows/orbit-worker.yml`, 검토한 40자리 `ORBIT_RUNTIME_REF`, `.orbit/policy.json`, `OPENAI_API_KEY` secret과 **ORBIT_API_WORKER_ENABLED=true**가 필요합니다. 별도 API/Actions 비용과 Linux Docker 실행 권한을 검토해야 하며, 기본 외부 ChatGPT 연결에는 해당 설정이 필요하지 않습니다. 이 worker의 제한된 도구/격리 검증 구조는 기술 결정0001에 기록되어 있습니다.

## 산출물과 만료

PDF/텍스트/소스 ZIP은 실제 파일에서 크기·SHA-256을 계산합니다. GitHub의 실제 산출물 업로드 확인 후에만 성공으로 표시합니다. 보존 기간은 workflow의 14일입니다. 다운로드는 인증된 조회→바이트 진행률→크기·체크섬 검증→저장 위치 선택→임시 파일의 원자적 교체 순서입니다. 같은 이름이 있으면 OS 저장 대화상자의 덮어쓰기 확인을 거칩니다. 파일을 실행하거나 설치하지 않습니다.

보존 기간이 지난 파일은 자동 재생성하지 않습니다. 결과함의 다시 요청으로 새 실행/산출물을 만들 수 있지만 선택한 외부 작업의 이용량이 다시 소모될 수 있습니다. 재실행 없는 만료 파일 재발급은 현재 미구현이며 RES-04에 기록했습니다.

## 뉴스·금융

뉴스 새로고침은 [동아일보 공식 RSS](https://rss.donga.com/)의 실제 한국어 제목/링크/게시 시각을 수집합니다. 키가 필요하지 않습니다. 피드의 개인 비상업적 이용 조건을 따릅니다. 전체·정치·의학과학·경제·도서 공식 피드를 합쳐 중복을 정리하고 분야별로 섞은 같은 스냅샷에서 24개씩 추가 로딩합니다. 새로고침은 최신 피드를 가져옵니다. 일부 피드 실패는 경고와 성공한 기사/기존 캐시를 함께 표시합니다. 검색은 캐시, 주제는 공식 RSS 분야와 제목 키워드입니다. 이전 HN 기사 중 저장한 기사는 유지하고 저장하지 않은 HN 캐시는 새로고침 시 정리합니다. 오프라인에서는 캐시와 오류를 함께 표시합니다. 원문 전문과 이미지, 실제 읽기 시간은 제공되지 않습니다.

금융은 Alpha Vantage 키를 설정합니다. 종목은 `GLOBAL_QUOTE`와 통화 확인용 `SYMBOL_SEARCH`, 지수는 `INDEX_DATA`를 사용합니다. 지수는 공급자 유료 권한이 필요합니다. API 한도·개인 사용/표시 조건은 공급자 문서와 계정에서 확인하세요. 잘못된 응답을 예시 시세로 대체하지 않습니다.

메인 뉴스 카드는 기사 있는 분야를 8초마다 순환합니다. 분야 버튼·이전/다음으로 직접 고르면 자동 전환이 멈추며 재생 버튼으로 재개할 수 있습니다. 마우스/키보드로 읽는 동안과 화면이 보이지 않을 때는 잠시 멈춥니다. 모션 줄이기에서는 직접 넘기기를 사용합니다. 뉴스 새로고침 후 새 분야가 메인 카드에도 반영됩니다.

## 진단

설정의 진단 보기에서 버전/스키마/큐 깊이/연결 상태를 확인할 수 있습니다. 지원용 진단 ID가 오류와 함께 표시됩니다. 로그는 데이터 폴더 `logs/orbit-YYYY-MM-DD.jsonl`에 보관하며 7일 후 삭제합니다. 요청 원문·키·기사 본문·검증 stdout은 기본 로그에 남기지 않습니다.
