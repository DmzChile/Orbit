# 설치와 연결

## Windows 앱

1. 검토한 설치 파일을 실행해 사용자별로 설치합니다. 현재 파일은 **미서명**입니다.
2. 처음 실행하면 빈 일정·보드·뉴스·결과함이 표시됩니다. 로컬 일정과 보드는 연결 없이 사용 가능합니다.
3. 기본 데이터는 Electron의 Windows 사용자 데이터 폴더 `%APPDATA%/orbit-desktop`에 저장됩니다. `ORBIT_DATA_DIR`를 지정한 경우 그 폴더가 기준입니다. `state.json`, 직전 `.backup`, DPAPI로 암호화한 `github.secret`/`alpha.secret`, `logs/`를 사용합니다. 설정에서 백업·복원·로컬 삭제를 제공합니다.
4. 설치 제거는 Windows 설치된 앱 또는 설치 폴더의 제거 프로그램을 이용합니다. 앱 제거는 사용자 데이터를 보존합니다. 완전 삭제 전에는 원격 예약을 중지하고 앱 설정의 로컬 초기화를 수행합니다. 원격 Issue/PR은 로컬 삭제로 제거되지 않습니다.
5. 자동 업데이트는 비활성입니다. 같은 데이터 스키마의 새 설치 파일로 수동 업데이트하거나 보관한 이전 설치 파일로 rollback합니다. 미래 스키마는 이전 앱이 덮어쓰지 않습니다.

## GitHub 연결

[GitHub의 fine-grained token](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens)을 만들고 **필요한 저장소만** 선택하세요.

| 권한 | 용도 |
|---|---|
| Metadata 읽기 | 계정·저장소 식별 |
| Contents 읽기 | 브랜치·기준 SHA |
| Issues 읽기/쓰기 | 요청·예약·영속 큐 댓글 |
| Actions 읽기/쓰기 | 실행기 확인·수동 시작·취소·산출물 |
| Pull requests 읽기 | 활동과 결과 확인 |

토큰을 Orbit 설정에서 연결하고 앱에서 허용할 저장소를 체크하세요. 연결 해제는 로컬 암호문을 폐기합니다. 공급자 쪽 토큰 철회는 GitHub에서 별도로 수행합니다. 토큰 만료/권한 철회/읽기 전용/404/API 한도를 구별해 표시합니다.

GitHub에 전송한 요청·결과는 대상 저장소의 공개 범위를 따릅니다. 개인 요청을 공개 저장소에 게시하지 않으려면 비공개 테스트 저장소를 선택하세요.

## 원격 실행기 설치 (선택 / 별도 비용)

아래 작업은 실행을 원하는 **대상 저장소에서** 검토 후 수행합니다. Orbit의 기본 브랜치 직접 push나 자동 merge가 필요하지 않습니다.

1. 이 저장소의 `.github/workflows/orbit-worker.yml`을 대상 저장소에 추가하는 PR을 검토·병합합니다. GitHub 예약은 기본 브랜치에 workflow가 있어야 실행됩니다.
2. 대상 저장소의 `AGENTS.md` 및 `docs/REQUIREMENTS.md`를 준비합니다. 실행 시 실제 checkout의 파일을 읽고 해시를 기록하며, AI 파일 도구도 두 문서 전체 읽기를 강제합니다.
3. `.orbit/policy.example.json`을 `.orbit/policy.json`으로 복사한 뒤 저장소·사용 가능한 API 모델·검증 스크립트·예산·시간 한도를 설정합니다. 검토 후 `enabled: true`로 바꿉니다. 예제는 비활성입니다. 지정한 모든 npm 스크립트가 실제 존재해야 합니다.
4. GitHub repository Actions 변수 **`ORBIT_RUNTIME_REF`**에 검토한 Orbit 구현 커밋의 40자리 SHA를 입력합니다. 워커는 해당 SHA의 런타임을 고정 사용합니다. 브랜치 이름은 거부합니다. 비공개 Orbit 포크를 사용하려면 workflow의 runtime repository와 최소 읽기 권한도 조정해야 합니다.
5. repository Actions secret **`OPENAI_API_KEY`**를 설정합니다. API 프로젝트의 모델 접근과 지출 제한을 확인하세요. 키는 앱·코드·요청 본문에 넣지 않습니다. ChatGPT 구독과 API 비용은 별도입니다.
6. 저장소 Actions 정책에서 workflow의 작업 브랜치/Issue/PR 쓰기 권한 및 PR 생성이 허용되어 있는지 확인합니다. 조직에서 금지하면 앱은 이를 우회하지 않습니다.
7. Orbit에서 초안을 작성하고 실행 경로·비용에 동의한 뒤 **실행기에 등록**합니다. 수동 요청은 **지금 실행**을 누릅니다. 예약은 GitHub가 약 5분마다 확인합니다. 결과함은 기본 60초 간격으로 자동 조회하며 지금 동기화도 가능합니다.

실행은 최신 기준 SHA를 별도 임시 checkout으로 가져온 뒤 이루어집니다. AI에는 파일 읽기·쓰기·삭제와 허용된 `npm run test/build/typecheck/lint`만 도구로 제공합니다. 검증은 **네트워크 없는 Docker 컨테이너**에서 수행합니다. 부모 실행기의 OpenAI/GitHub 키는 검증 컨테이너 환경에 전달하지 않습니다. Docker 실행은 Linux GitHub-hosted runner를 기준으로 작성했으며 실제 원격 연결 검증은 상태표를 확인하세요.

예약 중복은 결정적 실행 ID로 차단하고, 중단된 모델 작업은 자동 재과금하지 않습니다. 수신만 실패한 경우 이미 게시한 PR/산출물을 먼저 복구합니다. 수동 전송 응답을 잃은 경우 같은 ID의 영속 큐 댓글을 확인한 뒤 복구하며, 새로운 실행 ID로 무조건 재전송하지 않습니다.

## 산출물과 만료

PDF/텍스트/소스 ZIP은 실제 파일에서 크기·SHA-256을 계산합니다. GitHub의 실제 산출물 업로드 확인 후에만 성공으로 표시합니다. 보존 기간은 workflow의 14일입니다. 다운로드는 인증된 조회→바이트 진행률→크기·체크섬 검증→저장 위치 선택→임시 파일의 원자적 교체 순서입니다. 같은 이름이 있으면 OS 저장 대화상자의 덮어쓰기 확인을 거칩니다. 파일을 실행하거나 설치하지 않습니다.

보존 기간이 지난 파일은 자동 재생성하지 않습니다. 결과함의 다시 요청으로 새 실행/산출물을 만들 수 있지만 API 비용이 다시 발생할 수 있습니다. 재실행 없는 만료 파일 재발급은 현재 미구현이며 RES-04에 기록했습니다.

## 뉴스·금융

뉴스 새로고침은 Hacker News 공식 공개 API의 실제 링크/제목/시각을 수집합니다. 오프라인에서는 캐시와 오류를 함께 표시합니다. 원문 전문과 이미지, 실제 읽기 시간은 제공되지 않습니다.

금융은 Alpha Vantage 키를 설정합니다. 종목은 `GLOBAL_QUOTE`와 통화 확인용 `SYMBOL_SEARCH`, 지수는 `INDEX_DATA`를 사용합니다. 지수는 공급자 유료 권한이 필요합니다. API 한도·개인 사용/표시 조건은 공급자 문서와 계정에서 확인하세요. 잘못된 응답을 예시 시세로 대체하지 않습니다.

## 진단

설정의 진단 보기에서 버전/스키마/큐 깊이/연결 상태를 확인할 수 있습니다. 지원용 진단 ID가 오류와 함께 표시됩니다. 로그는 데이터 폴더 `logs/orbit-YYYY-MM-DD.jsonl`에 보관하며 7일 후 삭제합니다. 요청 원문·키·기사 본문·검증 stdout은 기본 로그에 남기지 않습니다.
