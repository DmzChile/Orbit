# 보안 경계와 남은 검증

- Windows 단일 사용자 앱이다. 다중 사용자 서버 인증을 제공하는 것으로 표시하지 않는다. 계정 간 데이터는 OS 사용자별 저장소와 DPAPI로 분리한다. DPAPI는 같은 Windows 사용자 권한을 가진 다른 프로세스까지 차단하는 경계가 아니다.
- 키는 `safeStorage` 비동기 DPAPI 경로로 암호화하며 사용할 수 없으면 평문으로 fallback하지 않는다. 연결 해제 시 암호문을 제거한다. 모델 운영 키는 GitHub Actions secret이다.
- 모든 IPC 입력과 저장 데이터는 스키마 검증을 통과해야 한다. 공급자 경계에서 인증/한도/오류를 변환한다. 로컬 보드 version 충돌은 덮어쓰지 않는다.
- 기사/요청/결과는 React 텍스트로 렌더링한다. 외부 HTML/Markdown을 실행하지 않는다. 정적 디자인 아이콘 문자열만 SVG markup으로 사용한다. 위험 URL·인증 URL·경로 순회·예약 파일명·체크섬 불일치를 차단한다.
- AI는 호스트 셸, 프로세스 환경, 임의 네트워크, GitHub 게시 도구에 접근하지 못한다. 제한된 source 파일 도구와 정책으로 정한 검증 도구만 호출한다. 규칙 파일 전체 읽기를 실제 실행 컨텍스트에서 강제한다. 경로 이탈·symlink·비밀 파일·보호된 규칙/정책 쓰기를 거부한다.
- 검증 컨테이너는 외부 네트워크 없음, 비밀키 없는 최소 환경, CPU/RAM/PID/시간 한도, read-only root와 `.git`, checkout만 쓰기를 허용한다. 실행 중인 컨테이너는 timeout 후 정리한다. 배포 runner에서 이 경계의 실제 검증은 아직 남아 있다.
- 의존성 설치는 고정된 정책의 명시적 allowDependencyInstall일 때만 `npm ci --ignore-scripts`로 허용한다. 임의 명령을 모델이 선택하게 하지 않는다. 검증 스크립트 자체는 대상 저장소의 코드이므로 sandbox 안에서만 실행한다.
- 요청·규칙 해시·기준 SHA가 고정되며 모델 이후 보호 경로와 파일 종류를 다시 검사한다. 기본 브랜치 직접 push·자동 merge·산출물 실행·설치는 하지 않는다. PR은 초안이며 사용자 검토가 필요하다.
- 수동 전송 중단은 동일 ID로 재조회 후 복구한다. 모델 작업 시작 후 실패는 자동 재실행하지 않는다. 산출물 업로드와 앱 수신은 PR 게시와 별개 상태이다.
- webhook 서버를 제공하지 않아 webhook 위조 경로는 없다. GitHub HTTPS 인증 조회, ETag·커서·중복/오래된 이벤트 처리로 수신한다.
- 현재 미서명 설치 파일이다. 코드 서명·운영 자동 업데이트·실제 원격 자격증명·만료 산출물 무재실행 재발급은 완료되지 않았다. 전체 보안 감사를 완료했다고 주장하지 않는다.
